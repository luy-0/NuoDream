# 二选一选择页验收记录（抽卡式卡片）

2026-10-31｜分支 `feat/jev-two-story-choice`｜执行：pi｜复核：Codex / 用户

本记录只覆盖选择页（`choosing`）的展示与交互。Jev 接入、`instructions`、`criteria`、候选顺序与二轮算法未改动；本地 dev server 全程保持运行（3000 端口），浏览器截图使用独立 headless Chrome 实例。

## 本轮改动

- 选择阶段不再渲染八面 `mask-orbit`，两张候选卡是唯一的面具焦点；匹配阶段（matching）与得面/入戏（mask/wearing）流程不变。
- 候选卡改为竖版抽卡卡面：复用 `public/dream-assets/ui/codex/card-front-frame-v2.svg` 作纯装饰边框，深色卡底、金线边饰、卡背封印（`card-back-seal-v2.svg`）。卡面只保留全彩面具图、面具名、以“你”称呼的疑问；未使用傩谱编号、已收录、剧名等标签。
- 进入 `choosing` 时两卡从中线略带旋转/错位依次落位，并在约 0.5s 内由背面翻至正面；不增加额外点击步骤。
- 点击/键盘激活后：选中卡上提发光，另一卡淡出（240ms），随后进入现有的“选定故事 → 得面 → 入戏”链路；重复点击由 `selectingRef` 阻止。`prefers-reduced-motion` 下取消落位动画与等待，立即进入得面。
- 八条用户可见疑问改为第二人称（“你”），不含“我”；画像表版本 `get-face.profiles.v1` → `get-face.profiles.v1.1`。仅改展示文案，Jev 请求中的 `instructions`、`criteria`、排序与二轮剔除逻辑不变。
- 布局：桌面两卡并排居中，标题与“都不贴近，重新描述”在卡外；手机 390x844 两卡并排、疑问 2 行可见；矮屏/窄屏允许纵向滚动，不裁切疑问或按钮。
- 标题下引导文案改为“两面已落在案前，翻开你更想面对的那一张。”，强调抽卡动作但不暗示随机决定命运；卡面可读内容仍只有面具名与疑问。
- 修复刷新/恢复 `choosing`、`mask` 时的 hydration mismatch：`useReducer` 初始化不再在客户端首帧读取 `sessionStorage`，服务端与客户端首帧统一为 `name`；挂载后才恢复，并在恢复完成前禁止持久化 effect 用初始空状态覆盖旧存储。浏览器控制台已无 hydration 报错。
- `POST /api/dream/candidates` 新增 `candidateScores` 仅用于接口透传与审计；选择页只解析、忽略该字段，不展示分数，也不写入选择文案。

## 可复核验证

### 自动化

```bash
npx vitest run src/features/get-face/get-face-ritual.test.tsx \
  src/domain/get-face/story-match-profiles.test.ts
npx tsc --noEmit
npm run lint
```

组件测试断言：
- `choosing` 阶段无 `.orbit-mask`，只有两张 `.choice-card`；
- 每张卡有 `.choice-card-inner`、`.choice-card-front`、`.choice-card-back`、`.choice-card-frame`、面具 `<img>`；
- 卡内文本不含 `傩谱`、`已收录`、`《》` 或两位编号，不含 `.choice-card-story`；
- 疑问均含“你”、不含“我”；
- 点击后先出现 `is-chosen` / `is-dismissed`，240ms 后进入 `mask`；reduced motion 下立即进入 `mask`；
- 画像表单测锁定版本号 `get-face.profiles.v1.1` 与第二人称文案；
- 候选响应即使携带原始 `candidateScores`，页面文本也不出现分数、概率或“得分”；
- 服务端 `renderToString` 始终输出 `data-phase="name"`（不读取 sessionStorage），客户端挂载后分别恢复到 `wish`、`choosing`、`mask`，且恢复后存储内容不被初始状态覆盖。
